# План проекта: ELT-пайплайн по биржевым данным MOEX (ISS API)

Портфолио-проект: ежедневная загрузка данных Московской биржи через открытый API в PostgreSQL и аналитика почти целиком на продвинутом SQL. Оркестрация через Airflow, всё поднимается через Docker Compose.

**Источник данных:** MOEX ISS API — `https://iss.moex.com/iss/`. Официальный, документированный, для данных с задержкой ключ не нужен. Лимиты щедрые (ориентировочно ~100 000 запросов в сутки).

**Находки разведки (TQBR, `securities.json`):**
- 4 блока: `securities` (паспорт бумаги, 506 строк), `marketdata` (торги за день, 506 строк), `dataversion` (версия данных и дата торгов, 1 строка), `marketdata_yields` (доходности, для акций пустой — 0 строк)
- В каждом блоке 3 ключа: `metadata` (тип каждой колонки: `string` + длина в байтах, `double`, `int32`, `int64`, `date`), `columns`, `data` → пригодится для DDL
- Все 506 строк пришли одним ответом — у этого эндпоинта пагинации нет (проверить на истории, п. 1.8)
- `securities` и `marketdata` описывают одни и те же бумаги, связь по `SECID` + `BOARDID` (будущий JOIN)
- Блок может прийти пустым — код должен проверять это до обращения к `data[0]` (иначе `IndexError`)

**Находки разведки (история SBER, `history/.../SBER.json?from=2026-01-01&till=2026-09-30`):**
- 2 блока: `history` (торговые дни) и `history.cursor` (служебный, 1 строка)
- За раз приходит не больше 100 строк: первая порция — с 2026-01-05 по 2026-05-27
- `history.cursor`: `TOTAL` = 189 (всего записей под запрос, считается заново на каждый запрос), `PAGESIZE` = 100 (максимальный размер порции), `INDEX` = номер первой записи порции (= параметр `start`). Вторая порция `start=100`: 89 строк, 2026-05-28 … 2026-09-30, без пропусков
- Колонки для `core.daily_candle`: `TRADEDATE`, `OPEN`, `HIGH`, `LOW`, `CLOSE`, `VOLUME` (штуки акций), `VALUE` (оборот в рублях = штуки × цена), `NUMTRADES` (число сделок). `WAPRICE` — средневзвешенная цена дня
- `CLOSE` (последняя сделка) vs `LEGALCLOSEPRICE` (официальная цена закрытия по правилам биржи, по ней считаются индексы) — берём `CLOSE`, чтобы свеча целиком строилась по сделкам; в `raw` хранится всё, решение обратимо
- `MARKETPRICE3TRADESVALUE`, `MP2VALTRD` — служебные обороты для расчёта «рыночной цены» (налоги/регуляторика), для свечи не нужны
- Без `params` (если даты не дошли до запроса) API молча отдаёт историю с 2013 года — проверять `response.url`
- Без `timeout=` запрос к недоступному серверу висит бесконечно
- Если `start` больше `TOTAL` (например, 200 при 189), приходит пустой `history` (0 строк) без ошибки

## 3. Extract / Load
- 3.1 Идемпотентность: повторный запуск не плодит дубли (`ON CONFLICT (security_id, trade_date) DO UPDATE`) — биржа иногда уточняет данные задним числом
- 3.2 Инкрементальная загрузка: только даты после последней загруженной, с учётом торгового календаря

## Словарик
- **API** — способ программе запрашивать данные у сервера напрямую, без браузера
- **Эндпоинт** — конкретный адрес API, отдающий определённые данные
- **JSON** — текстовый формат данных «ключ: значение», похож на словарь Python
- **ELT** — Extract, Load, Transform: сначала забрать и сохранить сырые данные, потом обрабатывать внутри базы
- **Виртуальное окружение (venv)** — изолированный набор библиотек для одного проекта
- **Docker / Docker Compose** — запуск сервисов (Postgres, Airflow) в изолированных контейнерах одной командой
- **Airflow / DAG** — планировщик задач; DAG — описание цепочки задач и порядка их выполнения
- **Идемпотентность** — повторный запуск даёт тот же результат, без дублей
- **Инкрементальная загрузка** — грузим только новое, а не всё заново
- **SCD2** — хранение истории изменений записи через периоды действия (`valid_from` / `valid_to`)
- **CTE / рекурсивный CTE** — именованный подзапрос `WITH`; рекурсивный умеет обходить деревья
- **Оконные функции** — расчёт по «окну» соседних строк без схлопывания строк (скользящие средние, ранги)
- **Materialized view** — сохранённый результат запроса, который пересчитывается по команде
- **EXPLAIN ANALYZE** — показывает, как база реально выполняет запрос и сколько это стоит
- **Партиционирование** — разбиение большой таблицы на части (например, по месяцам)
- **PATH** — список папок, в которых Windows ищет программу по её имени (`python`, `git`). Проверить, что запустится: `Get-Command python`
- **Execution Policy** — политика PowerShell, разрешающая или запрещающая запуск `.ps1`-скриптов (нужна `RemoteSigned`, чтобы работал `Activate.ps1`)
- **Коммит** — сохранённый снимок файлов проекта в истории git, у каждого есть уникальный хеш
- **Staging area (индекс)** — «черновик» следующего коммита; `git add` кладёт туда снимок файла в момент команды
- **.gitignore** — файл с правилами, что git не должен отслеживать; действует на свою папку и всё внутри, но не на уже отслеживаемые файлы
- **LF / CRLF** — невидимые символы конца строки: `LF` в Linux/macOS, `CRLF` в Windows
- **Traceback** — отчёт Python об ошибке; читать снизу вверх: тип и суть ошибки → строка кода, где она случилась
- **KeyError / IndexError / TypeError** — нет такого ключа в словаре / нет элемента с таким номером в списке / операция не подходит для этого типа объекта
- **Метаданные** — «данные о данных»: названия, типы, размеры колонок (в ISS — ключ `metadata`)
- **Remote / origin** — удалённая копия репозитория (у нас на GitHub); `origin` — общепринятое короткое имя для неё
- **Query-параметры** — часть URL после `?` в виде `ключ=значение&ключ2=значение2`; в `requests` передаются словарём через `params=`
- **Пагинация** — выдача данных порциями (страницами); следующую порцию запрашивают отдельно, указывая, с какой записи начать
- **f-строка** — строка с префиксом `f`, внутри которой `{выражение}` заменяется значением: `f"x = {x}"`
- **Отрицательный индекс** — `lst[-1]` — последний элемент, `lst[-2]` — предпоследний
- **Срез** — `lst[начало:конец]` — новый список из части элементов, `конец` не включается: `lst[:3]` — первые три
- **Offset-пагинация** — порции запрашиваются по номеру первой записи (`start`); простая, но при добавлении записей между запросами порции могут «съехать»
- **Свеча (candle, OHLC)** — сводка торгов за период: Open, High, Low, Close + объём
- **Средневзвешенная цена (WAPRICE)** — средняя цена сделок, где каждая сделка весит пропорционально своему объёму
- **while** — цикл «повторяй, пока условие истинно»; нужен, когда число повторов заранее неизвестно
- **break** — немедленный выход из цикла
- **append / extend** — `append(x)` кладёт в список один элемент `x`; `extend(список)` добавляет все элементы другого списка по одному
- **time.sleep(с)** — пауза в программе на указанное число секунд
- **Retry / exponential backoff** — повтор упавшего запроса с растущей паузой (1 с, 2 с, 4 с…); временные ошибки сервера часто проходят сами
- **Checkpoint** — контрольная точка: запомненный прогресс, чтобы после сбоя продолжить с места остановки, а не начинать заново
- **Предохранитель цикла** — максимум повторов, после которого цикл останавливается с ошибкой; защищает от вечного цикла, если внешний сервер ведёт себя не так
- **Сервер БД / клиент** — сервер (PostgreSQL) постоянно работает, хранит данные и ждёт запросов; клиент (`psql`, VS Code, Python) подключается к нему, отправляет SQL и получает ответ
- **Порт** — номер «двери» на компьютере, через которую программа принимает подключения; у PostgreSQL по умолчанию 5432
- **Образ (image)** — шаблон для запуска: программа + всё, что ей нужно; только для чтения, скачивается из Docker Hub
- **Контейнер** — запущенный экземпляр образа со своим состоянием; из одного образа можно запустить сколько угодно контейнеров
- **Volume** — папка-хранилище вне контейнера; данные в ней переживают удаление контейнера
- **Демон (daemon)** — фоновая служба, которая работает постоянно; у Docker демон выполняет просьбы клиента `docker`
- **Код завершения (exit code)** — число, с которым программа заканчивает работу: 0 — успех, другое — ошибка (`Exited (0)` в `docker ps -a`)
- **Тег образа** — версия после двоеточия: `postgres:18`; без тега берётся `latest` — «самая свежая», которая со временем меняется
- **Проброс порта (`-p 5432:5432`)** — связывает порт Mac с портом контейнера, чтобы программы на Mac могли достучаться до сервера внутри
- **Переменная окружения (`-e`)** — настройка, которую программа читает при запуске; так образ `postgres` получает пароль
- **Пейджер (`less`)** — программа постраничного просмотра длинного вывода (`(END)` внизу); выход — `q` (в английской раскладке!)
- **База данных / схема / таблица** — сервер содержит базы; база содержит схемы («папки»); схема содержит таблицы
- **numeric vs double precision** — `numeric` хранит число точно (для денег и цен), `double precision` — приближённо, быстрее, но с ошибками округления
- **CHECK-ограничение** — правило для строк таблицы (`CHECK (high >= low)`); строку, которая его нарушает, база не вставит
- **`INSERT` сопоставляет по порядку** — значения в `VALUES` попадают в колонки строго в порядке списка колонок; смысл база не проверяет
- **`docker start` vs `docker run`** — `start` запускает существующий остановленный контейнер, `run` создаёт новый
- **Push** — отправка локальных коммитов в удалённый репозиторий; `-u` связывает локальную ветку с удалённой

## История решений
- Изначально: вакансии hh.ru через API → с апреля 2026 поиск вакансий без авторизации закрыт, с 15.12.2025 прекращена поддержка API для соискателей (приложение можно зарегистрировать только от аккаунта работодателя)
- Рассмотрен скрапинг встроенного JSON со страницы поиска hh.ru — рабочий, но отложен: цель проекта — работа именно с настоящим API
- Рассмотрен SuperJob API (доступ для соискателей есть) — не выбран
- **Выбрано: MOEX ISS API** — открытый официальный API крупного игрока, данные естественно ложатся на оконные функции, корреляции и ежедневный DAG
- Окружение: `venv` + `pip` + `requirements.txt` — стандарт, который знают все; альтернативы `conda` (тяжёлая), `poetry`/`uv` (современнее, lock-файлы) — можно перейти позже
- Python 3.14 не в PATH (команда `python` вела на заглушку Microsoft Store) → окружение создаётся через лаунчер `py`; внутри активированного `.venv` работает обычный `python`. Airflow будет в Docker со своим Python, локальная версия ему не мешает
- `CLAUDE.md` исключён из репозитория через `.gitignore` — это личные инструкции для наставника, не часть проекта
- Переезд с Windows на macOS (окт. 2026): `.venv` пересоздан локально (Python 3.14.8), активация `source .venv/bin/activate`, терминал zsh. Контекст между машинами переносится через git (`docs/plan.md`), поэтому коммитить и пушить в конце каждой сессии
- `.venv/` явно указан в корневом `.gitignore`, хотя `venv` 3.13+ сам кладёт внутрь `.gitignore` с `*`: правило должно жить в репозитории и не зависеть от версии Python на чужой машине
